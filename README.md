# AI Code Review PoC

A working prototype that reviews GitHub pull requests using models hosted on
[GitHub Models](https://github.com/marketplace/models). It fetches the PR
diff, asks the model for structured findings, validates them against the
diff, and posts inline review comments back to the PR.

## What's in the box

```
ai-code-review-poc/
├── src/reviewer/           # Core library
│   ├── client.py           # Thin wrapper over azure-ai-inference
│   ├── prompts.py          # System + user prompt templates
│   ├── reviewer.py         # review_patch() — diff-scoped review
│   ├── github_poster.py    # Post inline comments on a PR
│   └── utils.py            # Dedup, line-number validation, filtering
├── scripts/
│   ├── review_pr.py        # Entrypoint used by the GitHub Action
│   └── review_local.py     # CLI for local experimentation
├── eval/
│   ├── harness.py          # Run N models across a corpus, score them
│   ├── build_corpus.py     # Regenerate all .diff/.labels.json from structured cases
│   └── corpus/             # 12 bug cases + 4 clean cases (FP tracking)
├── tests/                  # Unit tests for utils
├── .github/workflows/ai-review.yml
├── requirements.txt
└── .env.example
```

## Quick start (local)

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # then paste your GitHub PAT (models:read)

# Review a local diff file:
python scripts/review_local.py --diff eval/corpus/sample_01.diff \
    --model openai/gpt-4o-mini

# Compare models across the labelled corpus:
python eval/harness.py \
    --models openai/gpt-4o-mini openai/gpt-4o meta/llama-3.3-70b-instruct
```

## Quick start (CI)

1. Copy `.github/workflows/ai-review.yml` into the target repo.
2. Ensure the workflow has `permissions: models: read` and `pull-requests: write`.
3. Open a PR. The action posts findings as review comments.

## Model catalog

Any chat-completions model listed on GitHub Models works. Tested shortlist:

| Model id                            | Notes                          |
|-------------------------------------|--------------------------------|
| `openai/gpt-4o-mini`                | Default — cheap, fast, decent  |
| `openai/gpt-4o`                     | Higher recall, pricier         |
| `meta/llama-3.3-70b-instruct`       | Good OSS alternative           |
| `mistral-ai/mistral-large-2411`    | Strong on security findings    |
| `microsoft/phi-4`                   | Baseline / lint-like checks    |

## Evaluation

The leaderboard emitted by `eval/harness.py` reports:

| Column        | Meaning                                                           |
|---------------|-------------------------------------------------------------------|
| Recall        | hits / expected findings (across **bug** cases)                   |
| Precision     | hits / findings emitted (across **bug** cases)                    |
| FP/clean      | mean findings emitted per **clean** case (pure false-positive rate) |
| Tokens/case   | mean prompt + completion tokens per case                          |
| $/case        | estimated cost using `src/reviewer/pricing.py` list prices        |
| Latency/case  | mean wall time per case                                           |

The corpus covers: SQL injection, hardcoded secrets, N+1 queries, command
injection, TOCTOU races, null/undefined deref, path traversal, unsafe
deserialization, IDOR, off-by-one, broken retry/swallowed exceptions, SSRF,
XSS — plus 4 clean diffs (renames, new tests, type hints, dep bumps) that
any finding on is counted as a false positive. Add cases by editing
`eval/build_corpus.py` and rerunning it; diff hunk headers are generated by
`difflib` so they're always correct.

Override pricing at runtime via the `REVIEWER_PRICES` env var (JSON).

## Configuration

Drop a `.ai-review.yml` at the repo root to override the workflow's
defaults without forking the workflow yaml. Every field is optional;
unknown keys are warned and ignored.

```yaml
model: openai/gpt-4o-mini
min_confidence: 0.6
min_severity: low            # low | medium | high | critical
concurrency: 4
max_diff_chars: 8000
max_retries: 3
retry_base_seconds: 1.0
post_summary: true           # PR-level summary comment with token/$/latency
block_patterns:              # extra globs that never reach the model
  - "**/legacy/*"
  - "vendor/**"
models_by_language:          # per-language overrides; falls back to `model`
  python: openai/gpt-4o
  typescript: openai/gpt-4o-mini
```

Precedence (highest first): explicit CLI flag → `.ai-review.yml` → env var
set by the workflow → built-in default. Built-in path blocks (`.env`,
`*.pem`, `secrets/`, etc.) always apply on top of `block_patterns`.

## Design notes

- **Diff-scoped**: only added/modified lines are reviewed. Cuts cost and
  avoids dragging the model into unrelated code.
- **Strict JSON**: the model returns a schema-shaped object; anything else
  is dropped.
- **Validated line numbers**: findings referencing lines that aren't in the
  diff are rejected before posting (hallucination guard).
- **Confidence filter**: default cutoff `>= 0.6`.
- **Idempotent comments**: each AI comment is prefixed `[AI-REVIEW]` so
  stale ones can be cleaned up on the next push.

## Limitations

- Rate limits on the free GitHub Models tier — fine for PoC, not a busy
  monorepo.
- No cross-file reasoning beyond what fits in one diff chunk.
- Prompts leave your security boundary — check data policy before pointing
  at private code.
